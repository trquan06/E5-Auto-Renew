E5 AUTO RENEW — GITHUB PUBLIC RELEASE PLAN
============================================

Mục tiêu
--------
Chuẩn bị repository E5-Auto-Renew để public và phát hành trên GitHub an toàn,
có thể clone sạch, build, test và chạy theo đúng tài liệu mà không vô tình đưa
secret hoặc dữ liệu runtime vào Git/Docker build context.

Repository mục tiêu:
https://github.com/trquan06/E5-Auto-Renew

GHCR image chuẩn:
ghcr.io/trquan06/e5-auto-renew

Trạng thái khi lập plan
-----------------------
- Chưa có .github/ và Dependabot.
- Chưa có .env.example, .dockerignore và data/.gitkeep.
- .gitignore chưa bảo vệ đầy đủ database, key, sidecar và .env.*.
- README, Dockerfile, Compose, Portainer và docs vẫn còn tên/OWNER placeholder.
- PLAN.md và TASK_CHECKLIST.md đang claim một số automation chưa tồn tại.
- run.bat đang cd vào subfolder không tồn tại.
- Docker chạy UID/GID 10001 nhưng Compose dùng bind mount ./data; clean clone trên
  Linux có thể không cho container ghi database/key.
- Uvicorn đang trust forwarded headers từ mọi IP. Rate limiting dựa vào client IP,
  vì vậy đây là release blocker chứ không chỉ là hardening sau release.

Nguyên tắc thực hiện
--------------------
1. Không thay đổi behavior chính ngoài phạm vi release, packaging và security.
2. Không tick hoàn thành dựa trên việc đọc code; phải có lệnh hoặc bằng chứng verify.
3. Không commit .env, database, key, token, log, backup hoặc credential thật.
4. Không gửi các file trên vào Docker build context.
5. Documentation chỉ mô tả tính năng/workflow đã tồn tại và đã kiểm tra.
6. Secret từng xuất hiện trong Git public phải được rotate/revoke; xóa ở commit mới
   không đủ.
7. Giữ README.md và README.vi.md đồng bộ về command, URL, image, port và security.
8. Ưu tiên mặc định an toàn nhưng giữ đường nâng cấp rõ cho người dùng v1.

Mức ưu tiên
-----------
P0: Bắt buộc trước lần push/public đầu tiên.
P1: Bắt buộc trước GitHub Release/GHCR image chính thức.
P2: Hardening có thể làm sau bản release cơ bản nếu rủi ro đã được document rõ.

PHASE 4 — P0/P1: TRUSTED PROXY VÀ WEB SECURITY BASELINE
======================================================================

4.1 Không trust forwarded headers từ mọi IP (P0)
------------------------------------------------
Hiện --forwarded-allow-ips "*" cho phép client trực tiếp spoof forwarded headers,
ảnh hưởng URL/origin và có thể né rate limit dựa trên client IP.

Yêu cầu trước public release:
- bỏ wildcard mặc định;
- chỉ trust IP/subnet reverse proxy hoặc cung cấp cấu hình explicit;
- sau proxy phải đặt PUBLIC_BASE_URL là external HTTPS origin;
- document network topology và không expose port 8080 trực tiếp ra Internet;
- test spoof X-Forwarded-For/Host/Proto từ untrusted client không đổi identity/origin;
- test trusted proxy vẫn truyền đúng scheme, host và client IP.

4.2 Security headers (P1)
-------------------------
Vì admin JWT hiện nằm trong localStorage, thêm:
- Content-Security-Policy phù hợp static app local;
- frame-ancestors hoặc X-Frame-Options;
- X-Content-Type-Options: nosniff;
- Referrer-Policy;
- Cache-Control: no-store cho API nhạy cảm;
- HSTS chỉ khi HTTPS được kiểm soát tại edge/proxy.

Không làm hỏng FastAPI docs/OAuth popup; thêm test cho header quan trọng.

4.3 JWT cookie migration (P2)
-----------------------------
Đánh giá chuyển bearer JWT từ localStorage sang cookie HttpOnly, Secure,
SameSite=Lax/Strict. Nếu chuyển phải thiết kế CSRF protection, cập nhật login/logout,
expiry và test state-changing endpoints/OAuth popup.

======================================================================
DEFINITION OF DONE
======================================================================

Repository chỉ được coi là release-ready khi tất cả điều kiện sau có bằng chứng:
1. git add . không thể stage .env, database, key, sidecar, log hoặc runtime backup.
2. Docker context/image không chứa secret, runtime data hoặc Git metadata.
3. .env.example khớp source/Compose và không chứa credential thật.
4. Clean clone Linux chạy đúng Quick Start, kể cả quyền ghi data.
5. run.bat dùng đúng repository layout.
6. Không còn OWNER hoặc repo/image/path placeholder không chủ đích.
7. Trusted proxy không dùng wildcard mặc định và không thể spoof để né rate limit.
8. README song ngữ và docs phản ánh đúng implementation.
9. CI pass Python 3.11/3.12; pytest pass.
10. npm ci/build pass và generated frontend assets không lệch.
11. Docker non-root, health và persistent restart smoke test pass.
12. Dependency, secret-history và filesystem/container scans pass theo policy.
13. Dependabot được nhận cho pip, npm, Docker và Actions.
14. GHCR path/tags/architectures đúng và image pull-by-digest chạy được.
15. Không còn credential thật chưa rotate trong tree hoặc history.

Không tick release-ready nếu một gate chưa chạy vì thiếu Git, dependency, Docker hoặc
môi trường CI. Trường hợp đó phải ghi rõ NOT VERIFIED.
